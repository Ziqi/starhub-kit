## 1. 网关级物联网摄像头物理断云闸（`cam-gate.sh`）

商业云摄像头自带的“软件隐私遮蔽”依赖闭源固件承诺，无法从网络层自证清白。星枢在透明网关 `gw`（`192.0.2.11`）上实施**物理级双向解耦**：

1. **推流感知（`EYES ON / OFF`）**：在 `gw` 的 `iptables -t mangle FORWARD` 链统计摄像头（`ip_camera` · 示例 `192.0.2.61`）出站字节速率，驱动门口微控制器状态指示屏（`status_display` · 示例 `192.0.2.62`）实时点亮观看告警；
2. **一键物理断云（保留局域网直看）**：执行 [scripts/cam-gate.sh](../scripts/cam-gate.sh) `off` 时，直接在网关内核态插入 `iptables -t mangle -I FORWARD 1 -s 192.0.2.61 -o Meta -j DROP`，100% 阻断向外部云平台推流，而局域网内 RTSP / 本地直连画面不受影响。

## 2. 智能电视（Android TV）分应用代理与不断网软待机守则

1. **严禁设置系统全局代理**：
   - 严禁对智能电视（`smart_tv` · 示例 `192.0.2.63`）执行 Android 全局 HTTP 代理注入，确保国内流媒体客户端走原生宽带 CDN 直连（`:0`），仅在需要跨境访问的独立流媒体播放器内部单独指向网关 `192.0.2.11:7890`。
2. **严禁调用硬件断电休眠键码（软黑屏保活铁律）**：
   - 部分电视固件收到 `:6095 keycode=power` 或系统深度休眠键码后会直接切断主板 Wi-Fi 供电，导致后续无法通过局域网或语音唤醒；
   - 智能中枢网页与 CLI 的「息屏待机」动作必须统一实现为**不断网软黑屏保活待机**，保持 ADB `:5555` 与局域网控制通道 7×24 在线。

## 3. 局域网智能音箱播控与 `v2.0` 插件化接口

- 通过 `pyatv` 驱动局域网智能音箱（`smart_speaker` · 示例 `192.0.2.64`）实现 TTS 语音播报与大模型语音问答联动时，须固定兼容依赖版本（`srptools==1.0.1`）并使用进程级互斥锁串行化音频流推送，防止并发抢占断连。
- 关于如何将自定义智能硬件编写为标准 `HomeDriver` 插件接入 `StarHub Home OS v2.0-spec`，详见 [ROADMAP-v2.md](./ROADMAP-v2.md)。

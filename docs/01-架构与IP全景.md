## 1. 核心架构设计哲学

星枢（StarHub）架构旨在用一套**单点可声明、全链路可自愈、零供应商绑定**的工程体系，解决多地域极客家庭与小型算力实验室最棘手的四类基础设施难题：

1. **彻底消灭异地局域网撞段（Native `100.64.0.x` + `4via6`）**：
   - 废弃传统 Tailscale 裸子网路由（Subnet Router 广播整个 `/24` 或 `/32` RFC 1918 地址）；
   - 所有核心 LXC 服务容器（`gw` `.11`、`panel` `.13`、`home` `.22`）均在宿主机配置透传 `/dev/net/tun`，直接运行内核态 `tailscale0` 网卡获得原生 `100.64.0.x` 地址；
   - 不直接安装客户端的底层虚拟化母机（`pve` `192.0.2.10`）通过总闸 `gw` 发布 `4via6` 无状态 IPv6 映射地址（`2001:db8:4a6::10` 模式），无论主控笔电身处任何同名 Wi-Fi，路由永远 100% 精确命中。
2. **总闸透明网关确定性分域 DNS（零 `fallback:` 竞速）**：
   - 在 `gw`（`192.0.2.11`，同时在 `eth0` 挂载副 IP `192.0.2.12/24` 承接局域网主备双 DNS）启用 `stack: gvisor` TUN 与 `Fake-IP`（`198.18.0.0/16`）；
   - 移除传统 Clash 配置中盲目并发查询海外 DoT/DoH 的 `fallback:` 段，统一通过 `respect-rules: true` + `nameserver-policy` 实现确定性分域解析：
     - `+.ts.net` $\rightarrow$ `100.100.100.100#tailscale0`
     - `geosite:cn,private` $\rightarrow$ 国内低延迟 DoH（如 `https://dns.alidns.com/dns-query`）
     - `geosite:geolocation-!cn` $\rightarrow$ 单路复用代理隧道 DoH（`https://1.1.1.1/dns-query#USStandard`）
3. **手术刀级应用层 QUIC (`UDP/443`) 治理**：
   - 跨境代理链路上部分客户端（Apple TV+ FairPlay 媒体流、iOS Gmail App 鉴权与同步）在 `UDP/443` 半通或黑洞时会陷入 50 秒超时转圈；
   - 若一刀切全局 `REJECT UDP/443`，又会破坏 Google Cronet 引擎（导致 YouTube 字幕与高码率自适应缓冲异常）；
   - 星枢在 [mihomo-shared-guardrails.yaml](../scripts/profiles/mihomo-shared-guardrails.yaml) 中精确固化 `Section 12b`（12 条 Apple 媒体后缀）与 `Section 12c`（11 条 Gmail 精确域名）`UDP/443 REJECT` 规则，实现毫秒级无感回退 TCP/TLS，同时由 `starhub-doctor.py` 强制校验 YouTube Cronet 域名零误伤。
4. **三出口分级隔离与 BBR+FQ 队列标准**：
   - `vps1`（`USStandard` · 示例 `198.51.100.11`）：供主场网关 `gw` 与异地办公节点日常主力出海；
   - `vps2`（`USReality` · 示例 `198.51.100.12`）：供 7×24 高吞吐算力工作站 `studio` 一跳专享直连，避免大流量推理/下载挤占家庭办公带宽；
   - `vps3`（`USRackNerd` · 示例 `198.51.100.13`）：供同城级联中转与跨运营商灾备兜底；
   - 全部出口与自建 DERP 节点强制开启 `net.core.default_qdisc = fq` 与 `net.ipv4.tcp_congestion_control = bbr`。

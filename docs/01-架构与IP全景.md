## 1. 核心架构设计哲学

星枢（StarHub）架构旨在用一套**单点可声明、全链路可自愈、零供应商绑定**的工程体系，解决多地域实验室与小型算力集群最棘手的四类基础设施难题：

1. **彻底消灭异地局域网撞段（Native `100.64.0.x` + `4via6`）**：
   - 废弃传统 Tailscale 裸子网路由（Subnet Router 广播整个 `/24` 或 `/32` RFC 1918 地址）；
   - 所有核心 LXC 服务容器（`gw` `.11`、`panel` `.15`、`home` `.20`）均在宿主机配置透传 `/dev/net/tun`，直接运行内核态 `tailscale0` 网卡获得原生 `100.64.0.x` 地址；
   - 不直接安装客户端的底层虚拟化母机（`pve` `192.0.2.10`）通过总闸 `gw` 发布 `4via6` 无状态 IPv6 映射地址（`2001:db8:4a6::10` 模式），无论主控笔电身处任何同名 Wi-Fi，路由永远 100% 精确命中。
2. **总闸透明网关确定性分域 DNS（零 `fallback:` 竞速）**：
   - 在 `gw`（`192.0.2.11`，同时在 `eth0` 挂载副 IP `192.0.2.12/24` 承接局域网主备双 DNS）启用 `stack: gvisor` TUN 与 `Fake-IP`（`198.18.0.0/16`）；
   - 移除传统配置中盲目并发查询海外 DoT/DoH 的 `fallback:` 段，统一通过 `respect-rules: true` + `nameserver-policy` 实现确定性分域解析：
     - `+.ts.net` → `100.100.100.100#tailscale0`
     - `geosite:cn,private` → 国内低延迟 DoH（如 `https://dns.alidns.com/dns-query`）
     - `geosite:geolocation-!cn` → 绑定故障转移代理组 `AutoSelect` 的海外 DoH（`https://1.1.1.1/dns-query#AutoSelect`），**严禁把 DoH/DoT 硬绑定到单一出口节点**，杜绝单节点断流或超额拖垮全网海外解析。
3. **`Section 9a` 前置手术刀级应用层 QUIC (`UDP/443`) 治理**：
   - 跨境代理链路上部分客户端（Apple 流媒体 DRM、移动端 Gmail 鉴权与内嵌图附件同步）在 `UDP/443` 半通或 XUDP 黑洞时会陷入 50 秒超时转圈；
   - 若一刀切全局 `REJECT UDP/443`，又会破坏 Google Cronet 引擎（导致 YouTube 字幕与高码率自适应缓冲异常）；若把 Gmail 拦截规则放在广义 `googleapis.com` / `googleusercontent.com` 代理规则下方，则会被完全遮蔽失效；
   - 星枢在 [mihomo-shared-guardrails.yaml](../scripts/profiles/mihomo-shared-guardrails.yaml) 中固化 `Section 9a`（12 条 Apple 媒体后缀 + 21 条 Gmail/附件图片代理精确域名）前置 `UDP/443 REJECT` 规则，实现毫秒级无感回退 TCP/TLS，同时由 `starhub-doctor.py` 强制校验 YouTube Cronet 域名零误伤与零单节点 DNS 绑定。
4. **多出口语义化命名、源 IP 物理隔离与实时语音单跳分流**：
   - 出口节点采用语义化 IP 尾段/角色命名（如主力 `vps1` `EgressPrimary` `198.51.100.11`、工作站专享 `vps2` `EgressWorkstation` `198.51.100.12`、高流量机房兜底/中转 `vps3` `EgressRelay` `198.51.100.13`），全部节点强制开启 `net.core.default_qdisc = fq` 与 `net.ipv4.tcp_congestion_control = bbr`，并在 `sing-box` 服务端双端口监听 `:8080 + :443` 应对双运营商家宽 `:443` 限流；
   - **透明网关多客户端源 IP 物理隔离（`Section 9c`）**：先放行 `home_lan_cidr` 与 `GEOIP,private,DIRECT,no-resolve`，再以 `AND,((SRC-IP-CIDR,<IP>/32),(NOT,((GEOSITE,cn))),(NOT,((GEOIP,cn,no-resolve))))` 搭配底部 `SRC-IP-CIDR` 兜底，将主控笔电（`192.0.2.31` → `DevDedicated`）、4K 智能电视（`192.0.2.63` → `MediaDedicated`）与移动 `Exit Node` 隔离至不同上游出口，同时保证国内影视 App 与局域网流量 100% `DIRECT` 直连；
   - **跨运营商实时语音单跳隔离（`Section 9b`）**：常规流量由 `AutoSelect`（`fallback` 或 `url-test`）自动择优，实时语音 ASR 域名（如 `wisprflow.ai`、`deepgram.com`）固定走只含单跳直连节点的 `VoiceRealtime`（`type: fallback`）组，彻底规避双跳中转抖动与 `url-test` 频繁切线引发的断词。

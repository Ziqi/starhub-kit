## 1. 30 秒黄金故障定界树

1. **先跑一键门禁定界**：`./bin/starhub doctor`（离线排障跑 `./bin/starhub doctor --local-docs-only`）。
2. **Tailscale `100.64.0.x` 不通或高延迟抖动**：
   - 执行 `tailscale status` 与 `tailscale ping <peer>` 查看走的是 `direct` 还是 `relay "derp"`；
   - 若自建 DERP 断联，检查网关 Mihomo 规则是否遗漏 `DST-PORT,3478,DIRECT` 或 DERP 公网 IP `DIRECT` 豁免。
3. **Tailscale 在线但某节点 SSH 连不上**：
   - 切勿盲目重启宿主机！立即走自建跳板 `127.0.0.1:2201..2204` **带外反向 SSH 救命绳**（`ssh gw-rescue` / `ssh workstation-rescue` / `ssh site-b-node-rescue` / `ssh gpu-worker-rescue`）直接带外登录修复。
4. **特定 App（如 Apple 流媒体或移动端 Gmail 内嵌图）转圈 50s 后才加载**：
   - 典型跨境 XUDP `UDP/443` 黑洞特征：核查 `gw:/etc/mihomo/config.yaml` 中 `Section 9a` 精确域名 `UDP/443 REJECT` 是否位于广义 `googleapis.com` / `googleusercontent.com` 代理规则**上方**（严禁被下方宽泛规则遮蔽，也严禁误加全局 `UDP/443 REJECT`）。

## 2. 四路反向 SSH 救命绳体系（Out-of-Band Lifelines `:2201~:2204`）

当节点遭遇 Tailscale 进程假死、TUN 路由表锁死或 CGNAT 穿透失败时，四条直走底层物理网卡的反向 SSH 隧道提供独立于 Mesh 网络之外的第二生命线：

- **跳板服务端加固（`derp` `203.0.113.10`）**：
  - 创建无 Shell 登录权限的受限账号 `useradd -r -m -s /usr/sbin/nologin lifeline`；
  - 在 `/home/lifeline/.ssh/authorized_keys` (`0600`) 按节点逐行绑定端口限制：
    ```text
    restrict,port-forwarding,permitlisten="127.0.0.1:2201" ssh-ed25519 <GPU_WORKER_PUBKEY>
    restrict,port-forwarding,permitlisten="127.0.0.1:2202" ssh-ed25519 <SITE_B_NODE_PUBKEY>
    restrict,port-forwarding,permitlisten="127.0.0.1:2203" ssh-ed25519 <GW_PUBKEY>
    restrict,port-forwarding,permitlisten="127.0.0.1:2204" ssh-ed25519 <WORKSTATION_PUBKEY>
    ```
- **客户端部署**：运行 `./bin/starhub render --out-dir ./dist`，将生成的 `./dist/systemd/starhub-lifeline-*.service` 安装至对应节点 `/etc/systemd/system/` 并 `systemctl enable --now`。

## 3. 1 小时裸机灾难重建手册（1-Hour Bare-Metal Disaster Recovery）

### 3.1 海外 VLESS-Reality 出口节点 10 分钟重建
1. 在新购 Debian 12 VPS 启用内核 `bbr+fq`：
   ```bash
   printf "net.core.default_qdisc=fq\nnet.ipv4.tcp_congestion_control=bbr\n" >/etc/sysctl.d/99-starhub-bbr.conf
   sysctl --system
   ```
2. 安装 `sing-box`，套用本仓 [templates/singbox-reality-server.json.tmpl](../templates/singbox-reality-server.json.tmpl) 填入新生成的 UUID 与 `sing-box generate reality-keypair` 密钥对，启动 `sing-box.service`。
3. 在控制中枢更新 `STARHUB_GROUND_TRUTH.json` 对应 `egress_vps` IP，执行 `./bin/starhub render --in-place` 自动刷新防环规则。

### 3.2 Proxmox VE 核心三容器（`gw` / `panel` / `home`）45 分钟裸机恢复
1. **宿主机准备**：安装 Proxmox VE，创建 Debian 12 LXC 容器 `100` (`gw`)、`102` (`panel`)、`103` (`home`)；在 `/etc/pve/lxc/{100,102,103}.conf` 添加 `/dev/net/tun` 透传：
   ```text
   lxc.cgroup2.devices.allow: c 10:200 rwm
   lxc.mount.entry: /dev/net/tun dev/net/tun none bind,create=file
   ```
2. **渲染全套配置**：在 `panel` 克隆您的私有拓扑仓，执行 `./bin/starhub render --out-dir ./dist`。
3. **恢复三节点**：
   - `gw`：下发 `./dist/mihomo-gateway.yaml`（填入凭据后 `chmod 600 /etc/mihomo/config.yaml`）、`./dist/starhub-ts-mss-clamp.sh` 与 `./dist/cam-gate.sh`，执行 `tailscale up --advertise-exit-node`；
   - `panel` & `home`：分别安装 `./dist/starhub-dash-fw.sh` 与 `./dist/starhub-home-fw.sh` 开机守护服务并拉起业务容器；
4. **终验闭环**：执行 `./bin/starhub doctor` 确认全维度 `FAIL=0`。

## 3. 单向访问控制矩阵与敏感凭据 `0600` 规范

### 3.1 非对称单向受控矩阵（One-Way Control Matrix）

| 发起端 | 目标端 | 允许权限 | 强制边界控制 |
|---|---|---|---|
| **主控机 (`laptop` / `site-b-node`)** | 全网基础设施节点 | 双向管理 | 连入 `gpu-worker` 与 `workstation` 强制配置 `ForwardAgent no`、`IdentitiesOnly yes` |
| **单向受控训练机 (`gpu-worker`)** | 主控机 / 网关 / 跳板 `root` | **0 反向连入权限** | 不向任何上游节点写入训练机公钥；跳板仅开放 `nologin` `lifeline` 账号的 `permitlisten="127.0.0.1:2201"` 端口转发专钥 |
| **算力工作站 (`workstation`)** | 异地节点 & 共享办公局域网 | 单向隔离 | 通过主机防火墙（如 `pf` 或 `nftables`）阻断向异地私人节点反连及共享 Wi-Fi 入站探扫 |
| **云端 AI 沙箱 (`agent_sandbox`)** | `panel` / `home` | 仅限 HTTP `:3001` / `:8080` | 双栈防火墙 `STARHUB-BOT-NOSSH` / `STARHUB-BOT-NOSSH6` 在 `INPUT` 链首条硬 `DROP` TCP `:22` |

### 3.2 敏感凭据物理隔离标准
- 线上 `/etc/mihomo/config.yaml`、`/opt/starhub-*/.env`、`/usr/local/starhub/lifeline/id_ed25519` 统一锁定 `chmod 0600`；
- 仓库内的 `scripts/mihomo-config-backup.yaml` 必须保持 `secret: ""` 占位，每次提交由 `DIM4-SECRET-GUARD` 与 `DIM6-MIHOMO-GUARD` 双重校验。

## 4. 标准声明式变更与无损热加载 SOP

### 4.1 增删节点或轮换海外出口 IP 标准流程
```bash
# 1. 编辑唯一事实源 STARHUB_GROUND_TRUTH.json
$EDITOR STARHUB_GROUND_TRUTH.json

# 2. 一键重编译仓库内双栈防火墙、B2 引导脚本与 Mihomo 规则母版，并导出部署包
./bin/starhub render --in-place
./bin/starhub render --out-dir ./dist

# 3. 执行离线 EGM 3.0 门禁校验（要求 FAIL=0）
./bin/starhub doctor --local-docs-only
```

### 4.2 总闸 `gw` Mihomo 零断流热加载 SOP
```bash
# 语法预检通过后，经 :9090 RESTful API 热重载（不断存量 TCP/SSH 连接）
ssh gw '/usr/local/bin/mihomo -t -d /etc/mihomo'
ssh gw 'SEC=$(awk -F\" "/^secret:/{print \$2}" /etc/mihomo/config.yaml); \
  curl -fsS -X PUT "http://127.0.0.1:9090/configs?force=true" \
  -H "Authorization: Bearer $SEC" -H "Content-Type: application/json" \
  -d "{\"path\":\"/etc/mihomo/config.yaml\"}"'
```
